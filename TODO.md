# BIEM Cotiza — Fase 1: cuentas privadas y workspaces

- [x] **Esquema multi-tenant aditivo.** MySQL debe incluir workspaces, membresías, perfil comercial, productos, clientes, cotizaciones, ítems, secuencias y eventos de auditoría; las entidades comerciales deben incluir `workspaceId`, versiones, auditoría y borrado lógico, sin eliminar tablas ni datos existentes.
- [x] **Workspace personal seguro.** Al autenticarse, cada usuario debe obtener de manera idempotente un workspace personal y una membresía `owner`; el cliente no puede elegir un `workspaceId` ajeno para acceder a datos.
- [x] **Contexto y procedimientos protegidos.** tRPC debe resolver `user`, `workspace` y `membership`; `workspaceProcedure` debe rechazar solicitudes no autenticadas o sin membresía. Deben existir consultas para confirmar sesión y workspace activo.
- [x] **Autenticación obligatoria.** La aplicación debe mostrar una pantalla de acceso antes de cargar las pantallas comerciales y usar una sesión web validada en servidor, con cookie `webdev_app_session`, state/nonce de OAuth de vida corta y compatibilidad con Preview.
- [x] **Integridad y validación.** Las migraciones Drizzle deben aplicarse correctamente; TypeScript, lint y las rutas de health/auth/workspace deben pasar verificaciones. La implementación no debe publicar, eliminar funciones móviles ni sustituir todavía los datos de productos, clientes o cotizaciones guardados en AsyncStorage.
